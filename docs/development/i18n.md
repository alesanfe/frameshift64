# i18n — UI localization

BattleShip's modern UI layer supports runtime-translatable strings using a
gettext-style model: **the English source literal is the lookup key**.

## How it works

- `TR("Some text")` (defined in `src/core/i18n/Locale.h`) returns the
  translation for the active language, or the English literal when no
  translation exists.
- Translations live in `assets/lang/<code>.json` — flat JSON objects mapping
  English literal → translated string. They are staged next to the binary as
  `lang/<code>.json` by `StageAssetRecipes.cmake`.
- The active language is the CVar `gSettings.Language`
  (0 = English, 1 = Español, 2 = Français, 3 = Deutsch, 4 = Português),
  selectable under **Settings → General → Language**. Option labels are each
  language's native name so users can always find their way back.
- English is the identity language — it never loads a file. Missing files,
  unreadable/invalid JSON, non-string values, and missing keys all fall back
  to the English literal silently. Invalid CVar values clamp to English.
- Switching language takes effect on the next frame — no restart needed.

## Adding a translatable string

Wrap the literal at the point where it becomes user-visible:

```cpp
ImGui::TextWrapped("%s", TR("Your new label"));
ImGui::TextDisabled(TR("Count: %d"), n);          // varargs form: TR is the format
ImGui::Text("%s", fmt::sprintf(TR("File: %s"), name).c_str());
```

Rules:

- **Varargs widgets** (`ImGui::Text*`, `BulletText`, `SetTooltip`): you may
  pass `TR(format)` as the format string directly — placeholders then live in
  the translated string, which is what translators expect. Always make sure a
  translated literal cannot be reinterpreted dangerously: when a plain string
  is drawn via a varargs function, use the `"%s", TR(...)` form so `%` inside a
  translation is never treated as a format spec.
- **Non-varargs widgets** (`SeparatorText`, `TextUnformatted`, `Selectable`,
  `Button`, `CollapsingHeader`): take the label directly — `TR(label)` is the
  only argument, never `"%s", TR(...)`. `TextUnformatted("%s", x)` compiles
  but treats `x` as the `text_end` pointer — a silent out-of-bounds read.
- **Never concatenate** inside `TR(...)`: `TR("a" MACRO "b")` makes the
  extraction key stop at `"a"`. Use a placeholder instead:
  `TR("Backup: %s.bak present"), SSB64_O2R_NAME`.
- **Preserve placeholders exactly**: `%s`, `%d`, `%zu`, `{}`, `{:.0f}`, `##id`
  suffixes, and `\n` must appear identically in the translation.
- Keep technical identifiers, paths, and diagnostic tokens in English —
  the extractor filters them, but only wrap user-facing text to begin with.

## Updating translations

```bash
python tools/developer/i18n/extract_strings.py            # stats
python tools/developer/i18n/extract_strings.py --write    # regenerate catalog
python tools/developer/i18n/extract_strings.py --sync=es  # add missing keys
```

`assets/lang/catalog.json` is the extracted key set (committed so translators
can diff it). It is filtered out of the runtime staging — only language files
ship. Keys the extractor reports but a `.json` lacks render in English, so
partial translations are always safe to commit.

## Adding a language

1. Create `assets/lang/<code>.json` (copy `catalog.json`, translate values).
2. Add the entry to `kLanguageCodes` / `kMenuLanguageOptions`
   (`src/core/i18n/Locale.cpp`, `src/interfaces/presentation/PortMenu.cpp`).
3. Bump the `gSettings.Language` range in `src/core/config/schema.cpp`.

The font atlas covers Latin-1 Supplement + general punctuation, so Western
European scripts work today. CJK/RTL scripts need atlas changes in
`Menu.cpp` (`ImGuiIO::Fonts`) first.

## Smoke-testing

`tools/developer/testing/shoot_languages.py` seeds `gSettings.Language` into
the user config, launches the binary with the test hooks
(`SSB64_MAX_FRAMES`, `SSB64_SCREENSHOT_FRAMES`), and captures the Settings
menu for every staged language plus the three fallback paths (missing file,
malformed JSON, out-of-range index). It kills leftover `BattleShip.exe`
processes between runs — a crashed-but-alive instance can rewrite the shared
config late and stomp the next run's seed — and verifies the per-language
captures are pairwise distinct.

```bash
python tools/developer/testing/shoot_languages.py            # auto-detects the build
python tools/developer/testing/shoot_languages.py --bin out/build/components-verify
python tools/developer/testing/shoot_languages.py --only es fr
```

Captures land in `out/screens/lang-test/`. Run it sequentially — the shared
user config is global mutable state, so parallel runs race each other.

For deep debugging, `SSB64_I18N_DIAG=1` (test-hooks builds only) logs the
first eight `T()` lookups per process with table size and HIT/MISS — useful
to tell a silent pass-through from a real lookup.
