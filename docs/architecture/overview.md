```
### The decomp ↔ port boundary

The boundary is NOT "decomp knows nothing about src" — `components/decomp/src/sys/net*.c`
calls `port_coroutine_*`, `port_save_*`, `port_log`, `port_net_*` directly.
The real boundary is the **`port_*` extern "C" ABI**: decomp sources may only
reach port code through headers declaring that ABI (`game/port.h`,
`observability/port_log.h`, `platform/coroutine/coroutine.h`, transport and
integration headers). `check_module_deps.py` allows decomp→{leaf modules,
features, integration} and nothing else — a decomp file including
`presentation/` or `application/` is a structural bug.

### Module dependency rules

Enforced by `tools/analysis/lint/check_module_deps.py` (wired into `repo-checks.yml`
and `run_project_lint.py`); `config/lint/module-deps-baseline.txt` lists the
pre-existing violations as tracked debt — shrink, never grow.

- `application` → everything (composition root)
- `presentation` → leaf modules + features — never `integration/` internals, never decomp headers
- `features` → leaf modules / integration / netplay — never application / presentation
- `distribution` → leaf modules / platform / features — never application / presentation
- `netplay` → leaf modules / platform / integration — never presentation / features
- `resources` → leaf modules / integration — never application / presentation
- `platform` → observability only
- `compatibility` → decomp / observability — the N64 shim layer, no product code
- `integration` → decomp / libultraship / leaf modules — the adapter layer
- `observability` `persistence` `diagnostics` `game` `rendering` `config`
  → leaf modules only — no product deps (these replace the old `core/` catch-all)
- `decomp` → leaf modules + features + integration — never presentation / application / platform

Every `src/<module>/README.md` documents the same contract at the point of use.
```

## Generated code

Files marked `linguist-generated` in `.gitattributes` are regenerated by
tools, never hand-edited: `generated/include/*/reloc_data.*.h`,
`generated/src/us/RelocFileTable.us.*`, `generated/src/us/ssb64_reloc_rebuild.us.cpp`,
`assets/game/**/*.yml` and its `manifests/*.json`.
The generator is the source of truth (`tools/code-generation/`).

## Key Dependencies
- **libultraship** (Kenix3/libultraship) — replaces libultra with PC-native rendering, audio, input, resource management
- **Torch** (HarbourMasters/Torch) — asset extraction from ROM into .o2r archives via YAML configs
- **Fast3D** — translates N64 F3DEX2 GBI display lists to OpenGL/D3D11/D3D12/Metal
- **SDL2** — windowing, input, audio backend
- Reference ports: HarbourMasters/Starship (Star Fox 64), HarbourMasters/SpaghettiKart (Mario Kart 64)

## What NOT to Include in Port
- components/decomp/src/ovl8/, `components/decomp/src/db/` — Debug overlay/menu (kept on the
  `port-patches` branch of the decomp submodule only as headers transitively
  required by `sys/develop.h`; no `.c` files compiled)
- components/decomp/src/interfaces/audio/, components/decomp/src/particles/ — Asset authoring sources;
  the port consumes these via Torch instead. Removed from `port-patches`.
- components/decomp/src/libultra/{io,libc,os,sp,vimodes}/ — Replaced by libultraship.
  Removed from `port-patches`. Port still compiles `libultra/{gu,n_audio,audio}/`.
- Assembly files (`asm/`) — Port uses C code only
- N64 ROM or copyrighted assets — Users provide their own ROM
